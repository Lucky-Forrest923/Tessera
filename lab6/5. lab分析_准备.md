# 关于Lab的架构分析试题

各位同学：

根据考试内容说明，本次试卷的最后一道题将与 Lab6 相关。建议大家在复习时重新分析 Lab6 的整体设计，并将自己提交代码的架构整理并绘制在一页 A4 纸上。请注意：

1. **这张架构图需要与答卷一起提交** ，并请提前写好姓名和学号。
2. 架构质量本身**不作为**评分标准，这个是lab6评分的内容；它的作用主要是帮助阅卷人理解你的回答。
3. 架构图中 **建议** 展示较大粒度的 package 之间的关系，而不是过于细致地罗列所有类，除非你本身没有按照package进行组织。
4. 架构图应能够体现 Lab6 中的以下要求：
- 在TUI和GUI中尽可能复用代码，避免相同的逻辑复制到两套UI代码中。
- 插件式架构，能方便的以插件的形式扩展系统的功能。

考试中的题目会在 Lab6 的基础上提出新的功能需求，并要求你给出大致的设计思路或预测需要修改的要点。

要回答好这道题，并**不要求你的 Lab6 架构本身已经“完美”**；评分标准是：你需要在理解自己代码整体结构的基础上，能够：

1. 指出当前架构在应对这类需求迭代时可能存在的问题，以及可以如何调整。
2. 说明在现有或修改过的架构基础上，实现该变更的大致方法。
3. 可以用UML图表示
